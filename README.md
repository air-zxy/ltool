# ltool — uTools 风格的 Windows 启动器

C++20 / Qt 6 / vcpkg + CMake，只跑 Windows。界面本体都是 DLL 插件，主程序只剩热键、托盘、单实例、命令行自测。
**每一处"为什么这么做、实测多少"都整段挪到 [docs/notes.md](docs/notes.md)** —— 这里只留一行一条。

## 功能

| 功能 | 一句话 |
| --- | --- |
| 应用快速启动 | 四个来源：桌面与开始菜单的快捷方式、你指定的应用目录、**开始菜单里的打包应用**（MSIX/Appx，磁盘上没有 `.lnk` 的那一类 —— ChatGPT、Claude、设置、Teams 都算，这台实测 48 颗），再加上系统自带那几个；拼音全拼和首字母都能搜，按使用频率排序。**没命中工具直达时节的先后是：应用第一、网站第二**（网站那一组含关键字命中 / 网址直开 / 引擎兜底，三条现在共用一个「── 网站 ──」表头，以前那几行没表头、看着像挂在上一节底下）；命中工具直达（`b64`、`windows`、拼音直达）时直达仍占第 0 行、回车还是它，但**不铲平**应用那一节。`--plugintest` 数的是行号不是"在不在"（实测：搜 `renwu` 应用在第 0 行 / 网站第 3 行；搜 `windows` 工具第 0 行 / 应用第 2 行 / 网站第 11 行）。 |
| 全局呼出 | `Alt+Space` 在屏幕中上方弹搜索框，再按一次收起；被占用时自动降级。**点别处就立刻收起**：失焦那一条分得清"激活被 Windows 撤回"（回到呼出之前那个窗口）和"你真的点走了"（去了别的窗口），前者才等 600ms 复查，后者当场收（`SearchWindow::blurAction`，`--toggle` 那 13 条钉着）。 |
| 搜索 | 输入即搜：应用 / 文件 / 网站关键字三路同时出，全角先折半角。 |
| 文件搜索 | 常用目录实时监听（秒级）+ 全盘快照（管理员下 USN 增量约 0.5 秒）。 |
| 网站直达 | `gh` / `ld` / `gg` 直接开浏览器；带上参数就站内搜索。 |
| 电源直达 | 输入 `休眠` / `sleep` / `hibernate` 或 `关机` / `shutdown` / `shut` → 第一行就是它，回车立刻动手（不问第二遍）。中文只认整条相等，英文认命令行形状（`shut.exe`、`shut /f` 也算），所以搜"关机后怎么恢复文件"、`shutter`、`shutdown 怎么用` 都不会把机器关了；这台机器没开休眠时那一行会当场写明 `powercfg /h on`，而不是等你按下再报错。 |
| 下载走本地代理 | 程序里每一趟网络下载都先看代理：配置页「下载代理」那格填了就用它，**留空 = 自动用系统代理**（实测这台是 `127.0.0.1:9980`）。覆盖面由一道闸守着 —— `tools/proxy_gate.sh` 数每一处新建 `QNetworkAccessManager` 后面有没有紧跟一个代理决定（当前 8 处、漏 0 处），OCR 引擎包那 27.9MB 是它抓出来的第一颗。失败时那句话会点名这趟走的是代理还是直连。 |
| 开发环境初始化 | `init java` 这类命令检测组件，缺的按 Enter 用 winget 装。 |
| 管理 PATH | `path add <目录>` 改用户 PATH，写完广播 WM_SETTINGCHANGE。 |
| 注册表整理 | `reg` 体检卸载残留 / 失效启动项 / MuiCache，删之前自动备份 .reg。 |
| 设置窗 | 左侧菜单只有四行：网站 / 插件商店 / 配置 / 关于。语言并进「配置」那一页的一节，软件、下载器、定时任务是商店里的卡片。「配置」那一页自己又分两个 tab：**通用**（开机启动、热键、代理、清单地址、插件自动更新、右键、索引、应用目录、剪贴板、数据）/ **外观**（夜间·日间）。 |
| 夜间 / 日间 | 配置页「外观」那一行两颗单选，**拨一下当场生效**（不用重启、不用按保存）：默认夜间 = 这一版之前的样子。日间那套是 **iOS 设置页那种「浅灰页面 `#f2f2f7` + 纯白卡片 + 一道描边」**（他连否了两版："太白了换一个白色"、"太丑了太难受了"，第三版点名要苹果那套），对比度现算：正文 16.83:1、次级 5.07:1、白字压主色 `#0066CC` 5.57:1、启动器那圈描边 3.11:1、卡片描边 3.47:1。**苹果规范自己不过 AA**（次级文字 3.95:1、白字压 iOS 蓝 4.02:1），所以那两颗没照抄、按 AA 调深了；卡片那道线本来照抄了 iOS 的 separator `#d1d1d6`，一量只有 **1.52:1**（白卡压白页=没有线），也换成启动器那圈同一支 `#868a90`。颜色不再写死在页面上，全走 `src/Theme.{h,cpp}` 那张"角色 → 两套取值"表（原来散在 28 个文件、271 处字面量里，git grep 量的）；漏一处由 `tools/theme_gate.sh` 数出来（当前 34 处挂样式表的地方、漏 0 处、48 颗角色名无重复）。启动器那扇是无边框半透明窗，"搜索框在哪儿"只由那一圈描边说给你看。**切不动的一块如实说**：插件 dll 自己那些页（录屏、置顶窗、宫图…）各写了一份深色，要重新构建那 20 颗 dll 才跟着换，商店里装的那批不会；`--cliptest` 里那四条对比度判据只管剪贴板这一颗。 |
| F1 截图 | 全屏框选、悬停吸附到窗口、标注、置顶、图上划词取字（`plugins/capture`）。 |
| F2 录屏 | 录整块屏幕或某一个窗口，出普通 mp4，画质和画面两档可选（`plugins/record`）。选择窗没标题栏但**按住标题那一行能拖**；选中一条就在右边出**编码后**的实时预览（同一一路 WGC，不是另画一张示意图）；点条目只选中，开录要按中间那颗「开始录制」（或回车）。 |
| linux.do 盯帖 | 每隔几分钟（默认 10）拉一次 linux.do 最新帖，比标题和标签里的关键词（默认 福利/女装/公益 —— **比的是标题、标签和分类名**），命中就在托盘冒一句；**没打开过页面也在后台跑**（`plugins/linuxdo`）。 |
| 图片排版 | 四宫 / 六宫 / 九宫：把图拖进格子、空格子**点一下就能给它选一张图**（也可以整批拖进来，或用「添加图片…」）、从一格拖到另一格换顺序、点右上角 ✕ 拿掉那一张；按「生成宫图」**先把效果图弹出来给你过目**，背景色就在**这个弹框里挑**（换一下当场重画），按「保存这张」才认这个色、才落盘，按取消什么都不改（`plugins/grid`）。 |
| 剪贴板 | 复制过的文本和图片存成历史（**默认关**，配置页那颗开关才收），商店里这张卡打开是一墙**卡片 + 关键字过滤框**：每张卡三样 —— 复制的时间、那条的文案、是图片就带一块 120×84 的缩略图（一张卡 208×176，一墙自绘，不是每行塞一个控件）；内容、"图片"、尺寸、日期都筛得动，**点一张卡就放回剪贴板**（2026-10-21 他把原来要的"双击"改成点一下），选中按 Delete 去掉那一条（`plugins/clipboard`；收集那个时钟留在 core，搜索框里「剪贴板历史」那一节和配置页的开关读的都是同一份）。留多久由两条上限决定：**最多 200 条**，加上「**保留 N 天**」（配置页那个数字框，默认 7、选「不限」就只按条数）—— 超龄的一律清、图片文件跟着删，没超龄的仍受 200 条兜底（`clipboard/keepDays`）。 |
| 随机数生成 | 四档一排（**整数 / 小数 / 字符串 / UUID**），按下档位在切换的同时**当场就生成一批**（`plugins/random`）。整数档：上下界 + 数量 + 「不重复」—— 区间不够时**明说「只有 3 个不同的数，取不出 5 个不重复的」并清空结果**，不会少给几个当成功；窄区间走抽样洗（部分 Fisher-Yates），宽区间走"掷到没撞"。小数档：位数那一格夹在 0…12（写 99 也只给 12 位），并且**不给「不重复」这个口子**（位数一夹必然撞，函数被问就说不）。字符串档：四组字符集（数字/小写/大写/符号）+「去掉易混的 `0O1lI|`」，池子大小的算法**只有一份** —— 界面画的勾选框和判据验的字符范围读的是同一颗 `Rand::poolOf()`；勾了「字符不重复」而长度超过池子就报错，并说清"池子只有几个"。UUID：`8-4-4-4-12` 小写、不带大括号。结果区只读 + 「复制结果」（就地改口「已复制 ✓」）+「清空」；状态行常驻在所有动作行下面，**没生成过 / 生成好了 / 参数不对**三种情况各有一句话，切夜间·日间时那一行的颜色跟着重挂（不重挂就是"界面还挂着夜里那支绿"）。搜索框里打「随 7 个」直达：串里第一个整数当数量，认不出数字就老实返回 false。 |
| 修复 | 检测 .NET / VC++ / DirectX / UCRT，未装的一键 winget 安装。 |
| 广告弹窗 | 按标题和进程扫弹窗，可关闭 / 结束进程 / 加拦截名单，勾了每 60 秒自动拦。 |
| C盘清理 | 可清理位置 + 占用分析（矩形树图）；边扫边出数，每个盘留着结果。整盘结构可走 **MFT 直读**（一次内核枚举拿全盘，不进任何一个目录；要一次管理员授权，没授权、或这台机器的 Windows 不让读 `$MFT` 时自动回退遍历，状态行会点名走的哪条、为什么没走快的）。 |
| Windows 用户名 | 先把账户现状只读摆出来，改显示名 / 改账户名 / 新建用户都要人在界面上按下。 |
| 关于 | 版本号 + 检查更新 / 下载 / 装并重启三颗按钮，一件都不自动。检查更新走 `github.com/.../releases/latest` 那条 302（跟完重定向读 tag），**不碰 `api.github.com`** —— 匿名 api 是每台出口 IP 60 次/小时，多查几次就 403。 |
| 网络 | 网卡 DNS 一键切预设，提权执行，含刷新缓存和恢复 DHCP。 |
| 文件占用 / 粉碎 | 右键看谁占用着它、能结束那个进程；粉碎是三轮覆写后永久删除，不进回收站。 |
| 压缩包读写 | 右键解压 / 压缩：读靠 libarchive 十几种格式，写 .7z 用 7-Zip 自己的多线程编码器。 |
| 其他 | 托盘图标、单实例、空查询显示常用应用、运行日志。 |

每一项的实测数字、无界面判据（`--capgeo` / `--recq` / `--diskui` 那些）和踩过的坑，
整段挪到了文末的 **功能细节与实测** —— 门口这一张只说"是什么"。
界面背后是二十个 DLL 插件共用一份 `ltoolcore.dll`，见「工具插件」那一节。

## 构建

依赖：**Visual Studio 2022（MSVC）、CMake ≥ 3.24、vcpkg**（本机 `D:\vcpkg`）。

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_TOOLCHAIN_FILE=D:/vcpkg/scripts/buildsystems/vcpkg.cmake
cmake --build build --config Release
```

- 依赖走清单模式（`vcpkg.json`：`qtbase` + `libarchive` + `bit7z`）。加依赖只改这份 json 再重新 configure，
  别在仓库根裸跑 `vcpkg install`。
- 产物在 `build\Release\`：`ltool.exe` 305KB + `ltoolcore.dll` 1.63MB + `ltool-plugins\*.dll` **15 个**。
- 编译已经很快：全量重建 17.9 秒、改一个头 13.7 秒、什么都没改 2.5 秒。
- 文件索引：常用目录实时监听（秒级）；全盘靠快照，管理员权限下用 USN 日志做增量（约 0.5 秒）。

## 使用

- 托盘常驻；`Alt+Space` 呼出/隐藏搜索框（在鼠标所在那块屏的中上方），再按一次收起。
  **能把搜索框弹出来的就三条路，日志里每一条都报名字**（`show: 呼出（要求者=…）`）：热键、托盘图标左键单击（=单击即呼出，不是双击）、以及**再启动一次 `ltool.exe` 且不带 `--` 参数**（双击 exe / 快捷方式 / 任务栏那颗 —— 第二个实例把请求转交给常驻实例后自己退出）。右键菜单那几项带 `--compress-7z` 这种杠，走不到这条路。"它怎么自己出来了"先 `grep 要求者 log.txt`。
- 回车 / 双击运行，`↑↓` 选择，`Esc` 隐藏，右键有更多操作（打开所在位置 / 复制路径 / 加入 PATH）。
- 内置命令：`rescan` 重扫索引 ｜ `init [java|c++|node|python|rust]` 开发环境检测与安装 ｜
  `path [list|add <目录>|del <目录>]` 用户 PATH ｜ `reg [scan|clean]` 注册表体检 / 清理。
- 热键：`F1` 截图 ｜ `F2` 录屏 ｜ 文件与文件夹右键里有 ltool 那一组（占用分析 / 粉碎 / 解压 / 压缩）。

## 打包 + 安装

```powershell
powershell -File build\verify\deliver.ps1        # 构建 → abi（两棵 dll 对这份 core）→ stale（布局陈不陈）→ 接口号闸 → 打包 → 停旧实例 → 静默装 → SHA256 对账 → **把装着的每一颗对齐到刚编的这份** → 拿装好的 exe 再跑一遍 --plugintest → 重起
```

- 约 20~25 秒一圈。档位：默认 normal **22.08MB**（1.0.x 起是「开箱零插件」包：里面一颗插件 dll 都没有，只建一个空 `ltool-plugins\`，插件由商店按需拉）｜ `-Final` 21.8MB 那档是十二个 dll 都在包里时量的，没重测 ｜ `-Quick` 26.9MB ｜ `-NoBuild` 跳过构建。
- 版本号只有一处：`ltool.iss` 的 `#define MyAppVersion`，读不到就直接 FATAL。
- 交付判据是**逐个文件比 SHA256**（`ltool.exe` + `ltoolcore.dll` 两颗按哈希硬比）；插件目录不再"只报数"——
  1.3.0 起每一轮装完**逐颗对齐到刚编出来那一份**，报"本来就是这个哈希 / 换成新的 / 原来缺 / 多出 / 被占用没换成"，
  并且点名目录里那些 `.old.*`（商店卸载排队留下的，`PluginHost::scan` 不认这个后缀，所以不会多画卡片）。
  为什么必须对齐而不是比个数：core 的公开面一动，老插件要么装载失败、要么按老偏移读新结构体当场崩（10-20 磁盘清理那次）。
  单独跑一遍哈希对账：`powershell -File build\verify\shaall.ps1`。
- 装到哪：默认按用户装 `%LOCALAPPDATA%\Programs\ltool`，指定目录加 `/DIR="D:\software\ltool"`。
- 等价裸命令就三步：`cmake --build build --config Release` → `"D:\software\InnoSetup6\ISCC.exe" ltool.iss`
  → `installer\ltool-<版本>-setup.exe /VERYSILENT /NORESTART /SUPPRESSMSGBOXES`。

## CI（`.github/workflows/build.yml`）

编 Release → 跑无界面回归 → 打包 → artifact；**只有推 `v*` 标签才发 Release**。
带 `-beta.N` 的标签自动标 pre-release，而 `/releases/latest` 不认预发 —— 预发和稳定就靠标签分，客户端不用改。
同一分支后推的一次会顶掉前一次在跑的作业。

发一版三步：改 `MyAppVersion` → 推 `main` → `git tag v<一模一样的号> && git push origin v<那个号>`（第三步是对外的，人来按）。

**Release 那份说明由 `tools/make_release_notes.py` 生成**（不用 `gh --generate-notes`，那份拼出来是裸提交标题列表，
而这个仓库的提交信息本来就写着原因和实测数字）。形状：概述 → **一笔提交一节**（图标按标题里的关键词挑：
🐛 修 / 🧩 插件商店 / 🎨 界面 / ⚡ 性能 / ✅ 判据 / 📝 文档 / ✨ 新增）→ 资产表（每个文件是什么、多大、sha256 前 8 位）→
`Full Changelog` 的 compare 链接。它顺带生成 `installer/sha256.txt`（整批校验表，说明里点名了它就必须真在资产里，
CI 有一步专门核对这两颗文件名在不在资产列表里）。"上一个标签"是 `git describe <标签>^` 问出来的，
不是"最新的那个标签"—— 前者才是历史上在这之前的那一个。

**说明里的机器路径会被脱敏**：那把正文原样搬进公开页的椅子，也就会把「旧目录 `C:\Users\<你的名字>\AppData\...`」
这类实测路径搬上去（本仓库的真历史里就有一句）。`scrub()` 只认"家目录 + 用户名"那一段，换成 `%USERPROFILE%`；
`D:\software\ltool`、`%LOCALAPPDATA%` 这类文档要的路径一个字不动。两道闸都在 CI"每推都跑"那一栏：
`--check`（6 条，摘掉脱敏当场红 4 条）+ `tools/notes_history_leak_check.py`（拿真区间 171 行、或直接拿
将要发出去的 `release-notes.md` 量，判据按**形状**而不是按某个用户名 —— 这个文件自己要进公开仓库）。

**仓库本体也有一道**：`tools/tracked_leak_check.py`（CI"每推都跑"那一栏的第 3 道脱敏闸）扫 `git ls-files`
的每一张文件（当前 572 张），命中"家目录那一段是个**真**用户名"就红 —— 占位（`x`、`someone`、`zzname`、
`<用户名>`）在白名单里，所以它判的不是"出现过 `C:\Users` 这几个字"。这一颗是 2026-10-22 查出来的：
`build/verify` 里 16 个一次性探针、17 处真账号从 10 月起就躺在公开仓库，而 `.gitignore` 那条 `build/verify/*.sh`
**只挡了一半**（挡 .sh，挡不住 .ps1/.py/.js），何况对**已跟踪**的文件忽略规则根本不生效 ——
所以这里立的是一条会红的闸，不是一条看起来像规则的注释。反向验：塞一颗带 `C:\Users\<某个真账号>\...` 的
`git add -N` 探针进去 → `TRACKED_LEAK_HITS=1`、退出码 1；撤掉 → 0。

## 网站关键字

首次运行生成 `<数据目录>\webs.json`，可自行增删：

```json
{ "keys": ["ld", "linuxdo"], "name": "LINUX DO", "url": "https://linux.do" },
{ "keys": ["gh", "github"],  "name": "GitHub", "url": "https://github.com",
  "searchUrl": "https://github.com/search?q=%s" }
```

- `keys`：触发关键字（输入 `ld` 或 `linuxdo` 回车即打开 linux.do）
- `searchUrl`：可选；配置后输入 `gh qt6` 会提供"在 GitHub 搜索 qt6"
- 输入完整网址（如 `linux.do`）也会直接提供"在浏览器打开"
## 开发环境插件（JSON）

默认插件是 JSON 文件，放在 `<数据目录>\plugins\`（首次运行自动生成）：

```json
{
  "id": "go",
  "name": "Go 开发环境",
  "items": [
    { "label": "Go", "cmd": ["go", "version"], "wingetId": "GoLang.Go" }
  ]
}
```

软件页的"下载/版本"用 winget 实现：配置 `[install] path=D:\software` 后安装会尝试 `--location`（部分安装包不支持位置参数时会失败，属正常）。

- `cmd`：检测命令（是否存在 + 输出版本）
- `wingetId`：缺失时 Enter 触发的 winget 包（可省略，配 `note` 纯提示）

## 插件

二十个自带插件：DLL 修复 / 广告弹窗 / 磁盘清理 / 网络 / 注册表分析 / 开机启动分析（**选中一行点「禁用这一项」就能关掉这个应用的自启**，写的就是任务管理器 · 启动 那同一个开关；**系统服务默认不列**，勾一下才出来）/ Windows 用户名 /
JSON 格式化（**左边输入、右边看效果**：文本框在左、解析树在右） / Base64 编解码 / **右键动作** / **录屏** / **截图** / **软件** / **下载器** / **定时任务** / **语言** / **图片排版**（四宫/六宫/九宫）/ **linux.do 盯帖**（第一个后台自己会跑的）/ **剪贴板**（复制过的文本和图片，列表能按关键字过滤）/ **随机数生成**（区间取数·不重复抽取·随机字符串·UUID）——
第三方插件走同一条路，主程序里没有"内置工具"特判。其中软件 / 下载器 / 定时任务那三张是 2026-10-15 从设置页菜单里搬进来的：
菜单只剩 网站 / 插件商店 / 配置 / 关于 四行，语言并进「配置」那一节。

| 位置 | 是什么 |
| --- | --- |
| `ltool.exe`（305KB） | 热键、托盘、单实例、自测入口 |
| `ltoolcore.dll`（1.63MB） | 主程序和插件**共用的一份**实现（`Utils` / `DiskScan` / `InfoRow` / `Archive` / `CaptureHistory` …） |
| `ltool-plugins\ltool-<id>.dll` | 一个工具一个：本体 + 一层 `LToolPlugin` 壳 + 嵌在 dll 里的 `plugin.json` |

- 契约只有一份：`src/ltool-plugin.h`（现在 **API 4**）—— `apiVersion / id / name / desc / keywords / createPage / feedText / actions / invoke / save / load`。
  API 4（2026-10-20）不是接口加了什么，是**core 那一侧的公开面动了布局**（`DiskScan::Tree` 加两个 QString、
  `ClipboardStore` 加 keepDays、`CaptureHistory` 的行加 key/pixmap、`Utils::launch/revealInExplorer/trimWorkingSet`
  搬进 platform 缝）：10-16 编的老插件名字全齐、`LoadLibrary` 成功、按老偏移读新结构体 → 0xc0000005。
  号一升，这种插件在商店卡片上就写成"清单里的 Api 是 3，这台机器只认 4"，`QPluginLoader` 那道 iid 也自己拒 ——
  **从"进来崩"变成"拒之门外并说清"**。代价如实说：升到 4 的那一版，装着的旧插件全要重装的（商店里那颗"更新"点一下），
  所以这条号不能随便动，也不许忘了动 —— `tools/core_abi_gate.py` 盯着（公开头动了布局却没升号 = CI 红）。
- 三类插件：**卡片型**（插件商店一张卡，可开可递文本）、**动作型**（截图、录屏、右键那几件：入口留在主程序，按下之后 `PluginHost::invoke(动作名)` 转发）、**后台型**（`plugins/linuxdo`：没人按它也自己跑）。后台型靠 plugin.json 里 `"Activate": true` 挂牌 + dll 导出 `ltoolPluginActivate`，启动时由 `PluginHost::startBackground()` 按名字找它 —— **不走接口虚函数**：加虚函数要动 vtable，等于把 API 再推到 5，而「API 不等就拒装」会把用户装好的每一颗插件全挡在门外（10-20 那次推 4 是被 core 逼的，不是自己找的）。没挂牌的插件一个 dll 都不多装；挂了牌没导出符号 = 启动时点名报错，`--plugintest` 那 19 条（每个插件一条"牌与导出的符号一致"）也提前拦住。
- 能禁用也能**卸载**：卸载就是真删那个 dll（连它改名成的 `.off` 一起）。当场删不掉（这个进程已经加载过它 ——
  Qt 插件 unload 之后里面活着的控件就是悬空指针，所以我们不 unload）就记进待删表，下次启动第一件事删掉。
  两种情况界面上说两句不同的话："已卸载" / "已安排卸载 · 下次启动真删掉"。
- **右键那几项跟着「右键动作」插件走**：注册表里那几个静态项不会自己判断，所以"该不该在"= 配置里那个勾（`shell/intent`）**×** 提供者在不在了（`plugins/shell` 装着且没禁用）。卸载或禁用它 → 文件/文件夹右键里的 ltool 当场撤掉；装回来 → 自动写上，勾不用重勾。缺 `shell/intent` 这个键的老机器按注册表现状算（不然下次启动会把人家正在用的菜单悄悄撤掉）。
- **插件商店只有一面列表**，卡片就是条目：没拉清单时列本机 `ltool-plugins\` 里装着的那几个，
  拉过之后以**这次发版那份 `plugins-index.json`** 为准（本机装着而清单没列的排在后面，状态词「清单外」）。
  1.3.0 起这份清单和那批插件 dll 是**主仓库发版那一次构建的产物**（`tools/make_plugin_index.py` 现算 sha256/字节数，
  连同 dll 一起挂成 Release 资产），商店拼的是 `releases/download/v<我自己这版版本号>/…` ——
  插件和 core 从此同一个提交、同一次编译，"发一次商店"不再是独立的一件事（#91 的根就在这）。
  每张卡按自己的状态给按钮，按钮排在**卡片最底下一行**（不和状态词挤同一行）：没装的「装」；装了但哈希不同的「更新」+「禁用」+「卸载」（装了的东西不能因为版本旧就禁不掉、卸不掉）；
  装了的「禁用」+「卸载」；被改名的「启用」+「卸载」。大小一律说 **MB**（两位小数，卡片上不留裸字节数）。点卡片正文 = 装了的打开那张页、没装的就等于按那颗按钮。
- **卡片那面墙顶上常驻一行过滤**（2026-10-23）：一颗名称框 + 三档「全部 / 已装 / 未装」，两维是**与**的关系。名称那一维**只比卡片上那个显示名**（关键词、id 一概不算 —— 想按关键词找就用主搜索框）；
  状态那一维读 `PluginStore::countsAsInstalled` 那一份，界面不自己再判一遍：已装/可更新/与商店不同/清单外/已禁用算「已装」，能装/接口对不上/条目不能用算「未装」，排进待删表而文件还在盘上的那条算「已装」。
  下面那一行常驻一句话说清「筛出几张 / 共几张 / 被哪一维挡的」，0 命中也不留一面白墙；**正看着一张插件页时改过滤不把人拽回卡片墙**，重排欠着，按「返回商店」那一步才补（那一行会如实说「返回商店时才重排这一面」）。
- **页眉那颗「一键下载全部」**（2026-10-23）：把**整个商店里没装的那几颗**一次排进队列 —— 范围不跟着那行过滤走（跟着走就名不副实），接口对不上的、条目用不了的那几颗不排在里面，那一行会点名说"另有几颗用不了"。
  **就地两段确认**：第一下一颗都不动，只把「排几颗 · 大约多少」摆出来（按钮换成「确认这 N 颗」，宽度预留过、不撑那一排）；再按一次才真排队。中间只要拆过一次墙（点「刷新清单」、哪颗装完），那个 N 就是上一秒的商店了 ⇒ 确认自动收回，得重新按第一下看新的数。
  第二下走的是**同一条"一次只飞一颗"的队列**（他连点九颗那次崩的就是并行）：判据量到的是「一颗在飞 + 其余排着」，不是"两趟同时在飞"；被过滤挡在墙外那几张拿不到卡片控件，就传 `nullptr` —— 那条队列本来就允许"没地方写字、下载照样走完"。上一批还在飞时再按它不插队，那一行说"等它空了再按"。
- **插件撞了异常，程序不再跟着死**（2026-10-23）：全仓库只有**一份** `__try/__except` 壳（`PluginHost.cpp` 里的 `crossSeh`），五种"跨进插件"的调用全从它过 —— 建页 `buildPage()`、递文本 `feedInto()`、执行动作 `invokeInto()`、后台激活 `activateInto()`、装载时那一问 `apiVersionInto()`/自报动作 `actionsInto()`。产品那四个入口（`page()` / `feed()` / `invoke()` / `startBackground()`）各自只剩"找到那颗接口，再交给这一颗"。掉进 `0xc0000005` 那一类（2026-10-22 那次「b64 会闪退」就是它）时：不给页、日志和界面那一行点名是哪颗插件 + 异常码 + 指令地址，程序继续跑。**买到的是什么写清楚**：窗口不消失、证据留下来、半建那张不当好页缓存 —— **不是“这个 bug 被关住了”**，那一趟已经碰过坏内存，后面是带着未知损伤继续跑，所以 WER 转储和 `pe_rva` 那条取证路一律保留。非 Windows 那边这层**如实不装**（接信号要 `sigsetjmp`，从信号里继续跑更不可靠 —— 真要做得走进程隔离）。
- **装插件是排队的，一次只飞一颗**：他连点九颗那次崩了（07:43 的事件日志：`ltool.exe` 挂在 `Qt6Widgets.dll`，
  异常码 0xc0000005；程序日志最后九行是九颗「装好」，紧接着重扫到第 9 条就没了）。九条下载 + 九次改名 + 中途
  重扫/重排叠在一起是这一类的根，所以多出来的那几颗先在卡片上写"排在第几位"，一颗落地接下一颗，队列空了才重扫 + 重排一次。
- **拉插件走三级顺序**（`PluginStore::fetch`，清单和 dll 两段共用这一条）：先镜像前缀 + 原件**走直连**，
  都不成才走「下载代理」那一行，最后是原件直连；每条候选原地试两次（这条线路上"连上但不吐字节"是常态）。
  内置两条是这台机器量过的（`ghfast.top` 0.86s 可用；`gh-proxy.com` 2026-10-15 对这个文件 403，10-11 还是 8.3MB/s ——
  它随时可能换脾气，所以顺序和重试比"选对哪一家"重要）。镜像只在地址是 github 那两路时才套
  （`raw.githubusercontent.com` 和 `github.com/…/releases/download/…`），指到自己的服务器就不套。配置页「插件镜像前缀」那一行可换；状态行会说出这次**实际走的是哪条、试了几次**。
- **两件不同的事分开判**：清单里那一条**能不能从商店拿下来装**（`Api` 和宿主对不对得上，谓词只有一个
  `PluginStore::installable()`，界面只问它给不给「装/更新/换成商店那份」），和本机这一颗**能不能用**
  （宿主认不认得出那个 dll，决定点正文开不开得了一张页、禁不禁得掉、卸不卸得掉）。
  本机没装而 Api 对不上 = 「装不了」并说清是哪一侧旧；**本机装着就照旧能开**，那句写成
  「清单里的 Api 是 3，这台机器上的宿主只认 4：换不了商店那份 · 本机这颗照旧」
  （10-20 第二版就是把这两件并成一件，整张卡被锁死、连禁用/卸载都没了，他报的"还是点不开"是这一条）。
  元数据不齐也是点名说清楚，不默默少一张卡。
- **每天自动更新一次**（他 2026-10-21 点名，配置页「通用」那颗开关，**默认开**）：程序启动 15 秒后拉一趟清单，
  把**已经装着**而清单版本更新的插件一颗一颗换掉（一次一颗，和手动那路共用 `PluginStore::installEntry`，不另写下载路），
  全程不弹框、不 reload —— 换下来的那颗如果这个进程还加载着，文件当场已经换好，界面说"下次启动用新的"。
  一天只跑一次（`store/autoUpdateDate`），**先记日期再动手**，所以跑挂了也不会每次启动都刷网络。
  清单拉不到就用本地缓存那一份，并在商店那一行说清是哪一份。
  **不自动装新插件**：清单里出现以前没有的插件，仍要他在卡片上自己点「安装」（他拍的就是这条边界，
  `--storetest` 有一条钉着"满墙的新插件也不会被自动装"）。商店那一页常驻一行说上次跑的结果。
- 加一个插件：`plugins/<id>/` 放 `plugin.json` + 源码 + 一层壳（照 `plugins/network/networkplugin.cpp` 抄），
  再在 `CMakeLists.txt` 里 `ltool_add_tool(id IdPlugin 源文件…)` 加一行，并把 `ltool-<id>` 补进下面那条
  `add_dependencies(ltool ...)`（不点名挂上去，`--target ltool` 根本不编它，打包照旧装上一版 —— 2026-10-15
  加 grid 时踩的就是这条），以及 `src/main.cpp` 里 `--plugintest` 那张 `kTools` 名单（少了它，dll 在目录里
  也没人验）。卡片墙、搜索直达、商店全自动认它。
- 第三方仓库：[mateo-ki/ltool_plugin](https://github.com/mateo-ki/ltool_plugin) —— 独立编 dll 的 SDK 快照
  （`tools/make_sdk.py` 生成）+ 一份插件源码。**它不再是商店的供货渠道**：那边的 `dist/` 是手工把本机构建产物
  提交进 git 的，最后一次 10-16，而那边的 `plugins/` 是主仓库源码的分叉（diff 实测 8 颗不同，record 少整个
  `WindowPreview.cpp`）—— 这两件事合起来就是 #91。商店现在读主仓库 Release 的资产（上面那条）。
  想留着它当地图可以，要改插件请改主仓库，别改那头的分叉。
  那边的 CI 定义在本仓库 `plugin-ci/`（`build.yml` + `ci/annotate-fail.sh`，那份镜像连"12 个"都还没更新）。

## 配置与数据目录

**数据目录 = 软件目录下的 `data\`**（`<exe 旁边>\data`，不往 C 盘的 `%APPDATA%` 堆 —— 他 2026-10-21 点名）。
里面是：`config.ini`（配置）、`log.txt`（运行日志）、`apps.json`（应用索引）、`usage.json`（使用频率）、
`icons\`、`webs.json`（网站关键字）、`plugins\`（开发环境插件）、`deepindex.dat` + `usnstate.dat`（深索引）、
`backups\`（注册表删除前的 .reg）、`clipimg\`、`ocr\`（取字引擎）。

三档优先（`Utils::resolveDataDir`，`--pathcfg` 那 26 条钉着）：① `LTOOL_DATA_DIR` 环境变量
（自测沙箱和便携模式走这一档，**设了它就不搬家**）；② 软件目录写得进去就用它；③ 只读位置（比如塞进
`Program Files`）退回 `%APPDATA%\ltool` 并留一条日志。
**从老位置搬过来是一次性的**：老 `%APPDATA%\ltool` 还在、而新目录里既没有 `.migrated-from-appdata` 标记
也没有 `config.ini`（守卫不能写成"新目录是空的"——`dataDir()` 一被问到就 mkpath 并写下 `log.txt`）→
逐个复制并**按 sha256 对过**，
对不上的删掉半成品；**旧目录原样留着不删**（本机实测那一份 378 MB：深索引 320 + OCR 模型 33 + 剪贴板图 16），
日志会写出旧路径，什么时候清由人决定。搬家只在"正常启动"那一次做（命令行带 `--` 旗标的自测进程一律不搬）。
**复制之前，目标里那份"内容逐字节等于程序自带的默认表"的文件先让路**——"已有同名不覆盖"这条规矩
不能被程序自己刚写下的默认值满足：2026-10-21 就这么把 24 条网站关键字留在了老目录里、界面上只剩默认 2 条
（`--pathcfg` 里"整条链"那 5 条钉的就是这件事，反向验过：漏掉那一步当场红 3 条，量 helper 的 3 条反倒全绿）。
顺带一处：剪贴板历史在 json 里记的是**绝对路径**，所以每一格先按文件名在现在这个 `clipimg\` 里认一次
（那颗文件名就是图内容的 sha1，同名即同内容）——不然你按上面那句说明删掉旧目录之后，
"图不在了就不留空条目"会把那几十条**连条目一起**丢掉（`--cliptest` 有 6 条钉着，含真读一遍 `load()` 那两条）。
**两道"根本不该发生"的守卫**：① 自测旗标那一圈少了一个 —— `--plugintest` 以前不在沙箱名单里，
而 deliver 的 `installed` 那一栏跑的正是它，它就是往还没搬的目录里播下默认 `webs.json` 的那一手；
② `WebShortcuts::ensureDefaultWebs()` 和 `DevEnv::ensureDefaultPlugins()` 现在先问
`Utils::legacyMigrationPending()`：**这个目录还没接住你的真数据时，一个字节默认值都不许写**
（判断只有一份，拆成纯函数 `migrationPendingFor(legacy, now)` 让判据能直接问）。
已经搬过的那趟还会补一次（`Utils::backfillFromLegacy`：只补现在这份历史引用着、而本地缺的剪贴板图，
别的一概不动 —— 不然你删掉的往期图会被每次启动复活）。
手上一台已经卡住的机器可以用 `build/verify/migrate_ltool_data.ps1`（默认只报告，`-Apply` 才写盘）：
老目录里有而新目录里**缺**的文件按 sha256 对过补进去，两边都有但字节不同的**一个字都不碰**、只列出来给你看。

截图和录像也在软件目录下（`captures\`、`recordings\`，和 `data\` 平级）；配置页「数据」可改，
改完立即生效、只影响以后存的文件。在用的键：

```ini
[web]    engine=baidu          ; 默认搜索引擎 baidu / google / bing / duckduckgo
[index]  deep=true             ; 关掉就只搜常用目录；refreshHours=6 定时重建
[apps]   roots=…               ; 应用搜索的额外项目，一行一个目录或 exe 全路径；depth=3 往里几层
[paths]  captures=             ; 留空 = 软件目录下的 captures；recordings= 同理
[store]  autoUpdate=true       ; 每天一次的插件自动更新（只换已装的）；autoUpdateDate=今天跑过的日期
         indexUrl=             ; 留空 = 内置那条（和本机这版 core 同一次构建发出去的那份清单）
```

## 已知限制

- **要 Windows 10**（Qt 6.10 的下限，安装包写了 `MinVersion=10.0`；Win7/8.1 上以前是"装得上、双击没反应"）。Win10 内部还有两档：**F2 录屏要 1809 及以上**（用的是 Windows.Graphics.Capture），**Win10 N / KN 版没装 Media Feature Pack 时录屏也不可用**（两种都是那件功能起不来并说清原因，不会崩、也不会整个程序打不开）。夜间标题栏那颗 `DWMWA_USE_IMMERSIVE_DARK_MODE` 同样要 1809+，早的版本只是不变暗。
- 深索引增量（USN）要管理员权限；普通权限自动回退成"快照 + 定时遍历重建"，只是新鲜度略降。
- `reg clean` 里 HKLM 那部分要管理员（HKCU 不受影响）。
- `.7z` 那条依赖 exe 旁边的 `7zip.dll`（运行期按路径加载）：漏打包只有这一条报错，不会整个起不来。
- 截图取字的引擎（PaddleOCR det/rec + onnxruntime，约 28MB）不打进安装包，第一次用到时下载、之后离线；下不到就明说"没装上"。
- `Alt+Space` 被别的程序占了就自动降级到备选热键（日志和托盘都会说）。
